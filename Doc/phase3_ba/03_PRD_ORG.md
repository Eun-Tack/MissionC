## FR-ORG-01: 소속(Organization) 등록·관리

**한 줄**: 소속(회사·기관)을 등록하고 로고·색상을 부여하여 최상위 계층으로 관리한다. `[iet03]`
**비즈니스 가치**: 플링크데이터·한국보훈진흥원·KDInternational 등 복수 소속의 컨텍스트를 한 도구에서 분리 관리. `[iet03]`

### 데이터 필드

| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| name | string | Y | 1~100자 |
| logo_path | string (로컬 파일 경로) | N | jpg/png/svg ≤ 1MB |
| color | string (hex) | N | 기본 #6366f1 |

### Acceptance Criteria

```gherkin
Scenario: 소속 등록
  Given 소속 등록 화면(SC-14)이 열려 있다
  When  이름 "플링크데이터", 로고 파일을 입력하고 저장한다
  Then  organizations 테이블에 row가 생성된다
  And   로고 파일이 MC-Notes/.assets/logos/에 복사된다
  And   SC-14 계층 뷰에 소속 카드가 나타난다

Scenario: 로고 없이 등록
  Given 소속 등록 화면이 열려 있다
  When  이름만 입력하고 저장한다
  Then  소속 color의 이니셜 아바타가 로고 자리에 표시된다

Scenario: 소속 삭제 — 하위 사업 존재 시
  Given 소속에 연결된 사업이 1개 이상 존재한다
  When  소속 삭제를 시도한다
  Then  "하위 사업이 있습니다. 먼저 이동하거나 삭제하세요" 경고가 표시된다
  And   삭제되지 않는다
```

### 비즈니스 규칙

| BR-ID | IF | THEN | 출처 |
|-------|-----|------|------|
| BR-ORG-01 | 소속 삭제 시 하위 businesses > 0 | 삭제 차단 + 경고 | `[추론]` |
| BR-ORG-02 | 로고 파일 저장 | MC-Notes/.assets/logos/{org_id}.{ext} 로 복사 | `[추론]` |
| BR-ORG-03 | 소속 생성 | MC-Notes/{org_name}/ 폴더 자동 생성 | `[iet03]` |

### 테스트 케이스

| TC-ID | 시나리오 | 기대 결과 | 유형 | 우선순위 |
|-------|---------|---------|------|---------|
| TC-ORG-01-01 | 정상 등록 | DB row + 폴더 생성 | 통합 | P0 |
| TC-ORG-01-02 | 로고 1MB 초과 | 업로드 거부 | 단위 | P1 |
| TC-ORG-01-03 | 하위 사업 존재 시 삭제 시도 | 삭제 차단 | 단위 | P0 |

## FR-ORG-02: 사업(Business) 등록·관리

**한 줄**: 소속 하위에 사업·이니셔티브를 등록하고 프로젝트의 상위 컨테이너로 관리한다. `[iet03]`

### 데이터 필드

| 필드 | 타입 | 필수 |
|------|------|------|
| org_id | integer (FK) | Y |
| name | string | Y |
| description | string | N |

### Acceptance Criteria

```gherkin
Scenario: 사업 등록
  Given 소속 "플링크데이터"가 존재한다
  When  사업명 "플링크케어 사업"을 입력하고 저장한다
  Then  businesses 테이블에 row가 생성된다
  And   MC-Notes/플링크데이터/플링크케어-사업/ 폴더가 생성된다
  And   SC-14에서 소속 하위에 사업 카드가 나타난다

Scenario: 무소속 사업 (소속 미지정)
  Given 사업 등록 화면에서 소속 선택을 하지 않는다
  When  사업을 저장한다
  Then  org_id = NULL로 저장된다
  And   MC-Notes/무소속/ 하위에 폴더가 생성된다
```

### 비즈니스 규칙

| BR-ID | IF | THEN | 출처 |
|-------|-----|------|------|
| BR-BUS-01 | 사업 생성 | MC-Notes/{org}/{business}/ 폴더 자동 생성 | `[iet03]` |
| BR-BUS-02 | 사업 삭제 시 하위 프로젝트 > 0 | 삭제 차단 + 경고 | `[추론]` |
| BR-BUS-03 | org_id = NULL | MC-Notes/무소속/{business}/ 폴더 생성 | `[추론]` |

## FR-ORG-03: 소속-사업-프로젝트 계층 뷰 (SC-14)

**한 줄**: 소속 → 사업 → 프로젝트를 트리 또는 카드 계층으로 탐색하고 각 레벨에서 항목을 확인·생성한다. `[iet03]`

### 화면 레이아웃 (ASCII)

```
┌─────────────────────────────────────────────────────┐
│ [플링크데이터 🏢]  [한국보훈진흥원 🏛]  [+ 소속 추가]  │
└─────────────────────────────────────────────────────┘
│ 플링크데이터                                          │
│  ├─ 🗂 플링크케어 사업                                │
│  │   ├─ 📁 MC 개발 프로젝트  [진행중] ██████░░ 68%   │
│  │   └─ 📁 API 연동 프로젝트 [기획]   ░░░░░░░░  0%   │
│  └─ 🗂 ODC 개발 사업                                 │
│      └─ 📁 ODC v2.0          [완료]   ████████100%   │
│ 무소속                                               │
│  └─ 📋 태스크 12개 · 메모 8개                        │
└──────────────────────────────────────────────────────┘
```

### Acceptance Criteria

```gherkin
Scenario: 계층 탐색
  Given SC-14 계층 뷰가 열려 있다
  When  소속 카드를 클릭한다
  Then  해당 소속의 사업 목록이 펼쳐진다

Scenario: 프로젝트 진척도 표시
  Given 프로젝트에 연결된 items가 존재한다
  When  SC-14에서 해당 프로젝트를 본다
  Then  완료 항목 / 전체 항목 비율로 진척도 바가 표시된다

Scenario: 무소속 항목 접근
  Given 소속·사업 미연결 항목이 존재한다
  When  SC-14에서 "무소속" 섹션을 클릭한다
  Then  해당 항목 목록이 표시된다
```

## FR-CAL-01: 캘린더 뷰 (SC-13)

**한 줄**: 일·주·월 3가지 모드로 날짜 기준 항목을 표시하고 소속·사업·프로젝트 필터를 적용한다. `[iet03]`
**비즈니스 가치**: 분산된 일정·태스크·마감일을 시간축으로 통합 조망. `[iet03]`

### 뷰 모드

| 모드 | 표시 범위 | 항목 표시 방식 |
|------|---------|-------------|
| 일 (Day) | 24시간 타임라인 | 시간대별 블록 |
| 주 (Week) | 7일 그리드 | 날짜 컬럼별 블록 |
| 월 (Month) | 달력 그리드 | 날짜 셀에 점·칩 |

### 화면 레이아웃 (주간 뷰 ASCII)

```
┌─────────────────────────────────────────────────────┐
│ [일] [주▼] [월]     < 2026년 5월 4일 ~ 10일 >  필터▼  │
├────┬────┬────┬────┬────┬────┬────┬────────────────────┤
│ 시  │월4 │화5 │수6 │목7 │금8 │토9 │일10                │
├────┼────┼────┼────┼────┼────┼────┤                    │
│09  │    │팀미팅│    │    │    │    │                    │
│10  │[MC개발]│   │    │    │    │    │                    │
│11  │    │    │    │마감 │    │    │                    │
└────┴────┴────┴────┴────┴────┴────┴────────────────────┘
```

### Acceptance Criteria

```gherkin
Scenario: 주간 뷰 진입
  Given 네비게이션에서 캘린더 아이콘을 클릭한다
  When  SC-13이 열린다
  Then  현재 주의 7일 그리드가 표시된다
  And   scheduled_at이 있는 항목이 해당 날짜·시간에 블록으로 표시된다

Scenario: 소속 필터 적용
  Given 캘린더 뷰가 열려 있다
  When  필터에서 "플링크데이터"를 선택한다
  Then  해당 소속 하위 프로젝트의 항목만 표시된다

Scenario: 캘린더 블록 클릭 → 컨텍스트 패널
  Given 캘린더에 항목 블록이 표시되어 있다
  When  블록을 클릭한다
  Then  SC-04 컨텍스트 패널이 열린다 (FR-FLOW-03과 동일)

Scenario: 날짜 없는 항목 (Unscheduled)
  Given scheduled_at이 없는 태스크가 존재한다
  When  캘린더 뷰를 본다
  Then  화면 우측 "미배정" 사이드바에 표시된다

Scenario: 항목 드래그로 일정 변경
  Given 주간 뷰가 열려 있다
  When  항목 블록을 다른 날짜·시간으로 드래그한다
  Then  scheduled_at이 업데이트된다
  And   Today's Flow(SC-01)에도 즉시 반영된다
```

### NFR

| 항목 | 값 |
|------|---|
| 뷰 전환 속도 | ≤ 300ms |
| 월간 데이터 로드 | ≤ 500ms |

## FR-LABEL-01: 라벨 시스템 (이슈·체크·상태 라벨)

**한 줄**: 항목에 의미 있는 라벨(확인 필요·검토중·블로킹 등)을 붙여 빠른 식별과 필터링이 가능하게 한다. `[iet03]`

### 기본 제공 시스템 라벨

| 라벨명 | 색상 | 의미 |
|--------|------|------|
| 확인 필요 | 🟡 yellow | 누군가의 응답·결정 대기 |
| 검토중 | 🔵 blue | 현재 검토 진행 중 |
| 블로킹 | 🔴 red | 이 항목이 다른 것을 막고 있음 |
| 중요 | 🟠 orange | 우선 처리 필요 |
| 완료 대기 | ⚪ gray | 완료 처리 전 최종 확인 필요 |

### Acceptance Criteria

```gherkin
Scenario: 항목에 라벨 추가
  Given 항목 상세 또는 컨텍스트 패널이 열려 있다
  When  "확인 필요" 라벨을 선택한다
  Then  item_labels에 row가 저장된다
  And   Today's Flow·캘린더에서 해당 항목에 라벨 배지가 표시된다

Scenario: 라벨로 필터링
  Given Today's Flow 또는 캘린더 뷰가 열려 있다
  When  "블로킹" 라벨 필터를 적용한다
  Then  해당 라벨이 붙은 항목만 표시된다

Scenario: 커스텀 라벨 생성
  Given Settings > 라벨 관리 화면이 열려 있다
  When  라벨명 "검수 필요", 색상 #10b981을 입력하고 저장한다
  Then  labels 테이블에 type='custom' row가 생성된다
  And   이후 항목에 해당 라벨 적용 가능해진다
```

### 비즈니스 규칙

| BR-ID | IF | THEN | 출처 |
|-------|-----|------|------|
| BR-LABEL-01 | 시스템 라벨 삭제 시도 | 차단 — 시스템 라벨은 비활성화만 가능 | `[추론]` |
| BR-LABEL-02 | 항목에 라벨 추가 | Today's Flow + 캘린더 동시 반영 | `[추론]` |

## FR-FILES-01: 프로젝트 폴더 자동 생성

**한 줄**: 소속·사업·프로젝트·단계 생성 시 MC-Notes 하위에 계층 폴더를 자동 생성한다. `[iet03]`

### 폴더 구조 규칙

```
MC-Notes/
  {organization_name}/
    {business_name}/
      {project_name}/
        {stage_order}_{stage_name}/    예: 01_기획, 02_개발, 03_검토
  무소속/                              org 없는 항목
    {YYYY}/
      {MM}/
        {DD}.md                        일별 메모
  .assets/
    logos/                             소속 로고 파일
```

### Acceptance Criteria

```gherkin
Scenario: 프로젝트 단계 폴더 자동 생성
  Given 프로젝트 "MC 개발"에 단계 "02_개발"을 추가한다
  When  저장한다
  Then  MC-Notes/플링크데이터/플링크케어-사업/MC-개발/02_개발/ 폴더가 생성된다

Scenario: 폴더명 특수문자 처리
  Given 프로젝트명에 슬래시 또는 콜론이 포함된다
  When  폴더를 생성한다
  Then  해당 문자가 하이픈(-)으로 대체된 폴더명이 사용된다

Scenario: 폴더 이미 존재
  Given 동일 경로 폴더가 이미 존재한다
  When  프로젝트를 생성한다
  Then  기존 폴더를 재사용하고 오류 없이 연결된다
```

### 비즈니스 규칙

| BR-ID | IF | THEN | 출처 |
|-------|-----|------|------|
| BR-FILES-01 | 폴더명 특수문자 포함 | `/\:*?"<>|` → `-` 로 치환 | `[추론]` |
| BR-FILES-02 | 폴더 이미 존재 | 기존 폴더 재사용, 오류 없음 | `[추론]` |
| BR-FILES-03 | 소속/사업/프로젝트 이름 변경 | 폴더 rename + file_index 경로 일괄 갱신 | `[추론]` |
| BR-FILES-04 | Google Drive for Desktop 설정 시 | MC-Notes 폴더를 Drive sync 폴더 내에 위치하도록 설정 안내 | `[iet03]` |

## FR-FILES-02: 파일-프로젝트·단계 매핑

**한 줄**: 파일이 어느 프로젝트·단계 폴더에 속하는지를 자동으로 파악해 file_index에 기록한다. `[추론]`

### Acceptance Criteria

```gherkin
Scenario: 단계 폴더 내 파일 자동 매핑
  Given MC-Notes/플링크데이터/플링크케어/MC-개발/02_개발/스펙.md 가 저장된다
  When  watchdog가 감지한다
  Then  file_index에 project_id + stage_id가 자동 매핑된 row가 저장된다

Scenario: 폴더 밖 파일 (매핑 없음)
  Given MC-Notes/무소속/2026/05/04.md 가 저장된다
  When  watchdog가 감지한다
  Then  project_id = NULL, stage_id = NULL로 file_index에 저장된다
```
