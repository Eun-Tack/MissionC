## FR-FLOW-01: Today's Flow 메인 뷰

**한 줄**: 오늘의 항목을 시간순으로 나열하고 Anytime 묶음을 하단에 표시한다. `[iet03]`
**비즈니스 가치**: MC의 시작점. 없으면 항상 도구 전환 필요. `[iet03]`

### AS-IS → TO-BE

| 구분 | 내용 | 출처 |
|------|------|------|
| AS-IS | 캘린더·태스크·메모가 각기 다른 도구에 분산 | `[iet03]` |
| TO-BE | 한 화면에서 오늘의 모든 항목을 시간순으로 파악 | `[iet03]` |
| 변경 유형 | 신규(중) | |

### 입력

| 필드 | 타입 | 필수 | 유효성 |
|------|------|------|--------|
| 날짜 기준 | date (오늘 자동 결정) | Y | 자정 기준 |

### 처리 흐름

```
1. 앱 진입 → SQLite에서 today items 쿼리
2. 시간 지정 항목: scheduled_at 오름차순 정렬
3. 시간 미지정 항목: Anytime 묶음 (BR-FLOW-01)
4. 100개 이상: 가상 스크롤 (BR-FLOW-04)
5. → 렌더 (≤1초)
실패: 마지막 캐시 표시 + "재시도" 버튼
```

### Acceptance Criteria

```gherkin
Scenario: 오늘 항목 정상 로드
  Given MC 앱을 진입한다
  When  Today's Flow 화면이 열린다
  Then  오늘 날짜의 항목이 scheduled_at 오름차순으로 표시된다
  And   1초 이내에 렌더가 완료된다

Scenario: 시간 미지정 항목 Anytime 표시
  Given 시간이 지정되지 않은 태스크가 존재한다
  When  Today's Flow 화면을 열면
  Then  해당 항목이 타임라인 하단 "Anytime" 묶음에 표시된다

Scenario: 데이터 없는 날 (빈 상태)
  Given 오늘 등록된 항목이 0개다
  When  Today's Flow를 열면
  Then  빈 상태 안내 메시지가 표시된다
  And   Quick Capture 입력란은 항상 활성 상태다
```

### 테스트 케이스

| TC-ID | 연결 AC | 시나리오 | 입력 | 기대 결과 | 유형 | 우선순위 |
|-------|---------|---------|------|---------|------|---------|
| TC-FLOW-01-01 | AC-1 | 정상 로드 | 오늘 항목 5개 | 시간순 5개 렌더, 1초 이내 | E2E | P1 |
| TC-FLOW-01-02 | AC-2 | Anytime 표시 | 시간 없는 태스크 3개 | Anytime 섹션에 3개 | 통합 | P1 |
| TC-FLOW-01-03 | AC-3 | 빈 상태 | 항목 0개 | 빈 상태 메시지 + QC 입력란 | E2E | P1 |
| TC-FLOW-01-04 | — | 100개 초과 가상 스크롤 | 항목 120개 | 가상 스크롤, 렌더 지연 없음 | 성능 | P1 |

### NFR

| 항목 | 값 | 출처 |
|------|---|------|
| 응답 시간 | ≤ 1000ms (P95) | `[추론]` |
| 동시 사용자 | 1 (단일 사용자) | `[iet03]` |
| 보안 분류 | 내부 (로컬 전용) | `[iet03]` |

### Edge Cases

| 케이스 | 처리 |
|--------|------|
| 자정 직전 진입 후 자정 경과 | 뷰 자동 갱신 (날짜 변경 감지) |
| DB 읽기 실패 | 마지막 캐시 표시 + "재시도" 버튼 |
| 항목 100개 초과 | 가상 스크롤 (BR-FLOW-04) |

## FR-FLOW-02: 캘린더 토글

**한 줄**: 같은 데이터를 일/주/월 캘린더 뷰로 전환한다. `[iet03]`

### AS-IS → TO-BE

| 구분 | 내용 | 출처 |
|------|------|------|
| AS-IS | 캘린더와 태스크 리스트가 별도 앱 | `[iet03]` |
| TO-BE | 토글 클릭으로 동일 데이터를 캘린더 뷰로 전환, 추가 API 없음 | `[추론]` |
| 변경 유형 | 신규(중) | |

### Acceptance Criteria

```gherkin
Scenario: 일/주/월 뷰 전환
  Given Today's Flow가 열려 있다
  When  캘린더 토글을 클릭한다
  Then  동일한 항목이 캘린더 형식으로 표시된다
  And   0.5초 이내에 전환이 완료된다

Scenario: 캘린더 뷰에서 항목 클릭

  When  항목을 클릭한다

  When  "흐름 뷰" 토글을 클릭한다

```

| TC-FLOW-02-02 | AC-2 | 클릭 연동 | 캘린더 항목 클릭 | 컨텍스트 패널 오픈 | 통합 | P1 |

## FR-FLOW-03: 컨텍스트 자동 결합 패널 ⭐ MC 핵심 차별화

**한 줄**: 항목 클릭 시 우측 패널에 연결 태그·.md 메모·GitHub 이슈·진척도가 동시 표시된다. `[iet03]`
**비즈니스 가치**: MC의 존재 이유. 도구 단절 문제의 직접 해결. `[iet03]`

### AS-IS → TO-BE

| 구분 | 내용 | 출처 |
|------|------|------|
| AS-IS | 관련 메모·이슈 확인하려면 각 도구를 개별 열어야 함 | `[iet03]` |
| TO-BE | 항목 클릭 → 0.5초 이내 패널에 모든 컨텍스트 동시 표시 | `[iet03]` |
| 변경 유형 | 신규(대) — MC 핵심 아키텍처 | |

### 출력 (Context Panel 구성요소)

| 출력 항목 | 조건 | 형태 |
|---------|------|------|
| 연결 태그 목록 | 항상 표시 | 칩 배지, 클릭 시 해당 태그 뷰 |
| 연결 정식 프로젝트 | 있을 때 | 프로젝트명 + 진척도 바 |
| 연결 .md 메모 미리보기 | 있을 때 | 첫 3줄 미리보기 + "전체 보기" 링크 |
| GitHub 이슈 목록 | repo 연결된 프로젝트 포함 시 | 이슈 번호·제목·상태 |
| 연결 항목 없음 | 0개 | "아직 연결된 컨텍스트가 없습니다" |

### Acceptance Criteria

```gherkin
Scenario: 컨텍스트 패널 정상 펼침
  Given 항목이 태그·메모·GitHub 이슈에 연결되어 있다
  When  항목을 클릭한다
  Then  우측 패널이 0.5초 이내에 펼쳐진다
  And   연결 태그·메모 미리보기·GitHub 이슈가 동시에 표시된다

Scenario: 연결 없는 항목 클릭
  Given 항목에 아무 컨텍스트도 연결되지 않았다
  When  항목을 클릭한다
  Then  패널이 열리고 "아직 연결된 컨텍스트가 없습니다"가 표시된다

Scenario: 패널 열린 상태에서 다른 항목 클릭
  Given 항목 A의 컨텍스트 패널이 열려 있다
  When  항목 B를 클릭한다
  Then  패널이 항목 B의 컨텍스트로 갱신된다 (BR-FLOW-02)

Scenario: GitHub repo 미연결 프로젝트 항목
  Given 항목의 프로젝트에 GitHub repo가 연결되지 않았다
  When  항목을 클릭한다
  Then  GitHub 이슈 섹션이 표시되지 않는다
```

### 테스트 케이스

| TC-ID | 연결 AC | 시나리오 | 입력 | 기대 결과 | 유형 | 우선순위 |
|-------|---------|---------|------|---------|------|---------|
| TC-FLOW-03-01 | AC-1 | 패널 응답 시간 | 항목 클릭 | 0.5초 이내 렌더 완료 | 성능 | P0 |
| TC-FLOW-03-02 | AC-1 | 전체 컨텍스트 표시 | 태그+메모+이슈 연결된 항목 | 3종 모두 표시 | 통합 | P0 |
| TC-FLOW-03-03 | AC-2 | 빈 상태 | 연결 0개 항목 | 빈 상태 메시지 | E2E | P1 |
| TC-FLOW-03-04 | AC-3 | 패널 갱신 | A → B 클릭 | B 컨텍스트로 교체 | 통합 | P1 |

### NFR

| 항목 | 값 | 출처 |
|------|---|------|
| 패널 펼침 응답 | ≤ 500ms (P95) | `[iet03]` |
| .md 미리보기 로드 | ≤ 200ms (로컬 파일 읽기) | `[추론]` |
| GitHub 이슈 | 캐시 우선. 실시간 조회 최대 2초 | `[추론]` |

## FR-CAP-01: Quick Capture (한 줄 입력)

**한 줄**: 어디서든 접근 가능한 단일 입력창으로 텍스트를 캡처하고 타입·시간을 자동 분류한다. `[iet03]`

### AS-IS → TO-BE

| 구분 | 내용 | 출처 |
|------|------|------|
| AS-IS | 메모 앱·캘린더·태스크 앱 각각 열어야 입력 가능 | `[iet03]` |
| TO-BE | 단일 입력창에서 타입 자동 분류 + 미리보기 확인 후 등록 | `[추론]` |
| 변경 유형 | 신규(중) | |

### 입력

| 필드 | 타입 | 필수 | 유효성 | 오류 메시지 |
|------|------|------|--------|-----------|
| 텍스트 | string | Y | 1~10,000자 (BR-VAL-01) | "내용을 입력하세요" / "너무 긴 입력입니다" |
| 타입 | enum (auto / 수동) | N | 자동 분류 후 미리보기 | — |

### 처리 흐름

```
1. 텍스트 입력
2. 시간/태스크/메모 패턴 감지 (BR-CAP-02~04)
3. 타입 분류 결과 미리보기 표시 (BR-CAP-01 — 사용자 확인 필수)
4. Enter 또는 확인 클릭 → DB 저장 → 0.3초 이내 흐름 반영
실패: 입력 보존 + "다시 시도" 토스트
```

### Acceptance Criteria

```gherkin
Scenario: 일정 텍스트 자동 분류
  Given Quick Capture가 열려 있다
  When  "내일 3시 팀 미팅"을 입력하고 Enter를 누른다
  Then  타입 "일정", 시간 "내일 15:00"으로 분류된 미리보기가 표시된다
  And   사용자가 확인 클릭 후 저장된다

Scenario: 빈 입력 거부
  Given Quick Capture가 열려 있다
  When  아무것도 입력하지 않고 Enter를 누른다
  Then  "내용을 입력하세요" 인라인 오류가 표시된다
  And   저장되지 않는다

Scenario: 10,000자 초과 입력
  Given Quick Capture에 10,001자를 입력했다
  When  확인을 시도한다
  Then  "너무 긴 입력입니다. 메모로 전환하시겠어요?" 다이얼로그가 표시된다

Scenario: 분류 결과 수동 수정
  Given 자동 분류 결과가 미리보기로 표시되었다
  When  사용자가 타입을 "태스크"로 수동 변경하고 확인한다
  Then  수동 선택 타입으로 저장된다
```

### 테스트 케이스

| TC-ID | 연결 AC | 시나리오 | 입력 | 기대 결과 | 유형 | 우선순위 |
|-------|---------|---------|------|---------|------|---------|
| TC-CAP-01-01 | AC-1 | 일정 분류 | "내일 3시 팀 미팅" | 타입=일정, 시간=내일 15:00 미리보기 | E2E | P0 |
| TC-CAP-01-02 | AC-2 | 빈 입력 거부 | 공백만 | 오류 메시지, 미저장 | 단위 | P0 |
| TC-CAP-01-03 | AC-3 | 10000자 경계 | 10000자 정확히 | 저장 성공 | 단위 | P1 |
| TC-CAP-01-04 | AC-3 | 10001자 초과 | 10001자 | 메모 전환 제안 다이얼로그 | 단위 | P1 |
| TC-CAP-01-05 | AC-4 | 수동 타입 변경 | 자동=메모 → 수동=태스크 | 태스크로 저장 | 통합 | P1 |
| TC-CAP-01-06 | — | 저장 속도 | 정상 입력 | 0.3초 이내 흐름 반영 | 성능 | P1 |

### NFR

| 항목 | 값 | 출처 |
|------|---|------|
| 저장 → 뷰 반영 | ≤ 300ms | `[추론]` |
| 보안 분류 | 내부 (로컬) | `[iet03]` |

## FR-CAP-02: 다중 태그 인라인 추가

**한 줄**: Quick Capture 또는 항목 편집 시 `#태그명`으로 태그를 즉시 추가한다. `[추론]`

### Acceptance Criteria

```gherkin
Scenario: 기존 태그 인라인 추가
  Given "프로젝트 A" 태그가 존재한다
  When  Quick Capture에 "오늘 할 일 #프로젝트A"를 입력하고 저장한다
  Then  항목이 "프로젝트A" 태그와 함께 저장된다

Scenario: 신규 태그 자동 생성
  Given "신태그" 태그가 존재하지 않는다
  When  "#신태그"를 포함한 항목을 입력한다
  Then  "신태그" 태그 생성 확인 다이얼로그가 표시된다
  And   확인 시 태그가 생성되고 항목에 추가된다

Scenario: 태그 자동완성
  Given "프로젝트" 접두어를 가진 태그가 3개 있다
  When  Quick Capture에 "#프로젝"를 입력한다
  Then  기존 태그 목록이 자동완성 드롭다운으로 표시된다
```

### 테스트 케이스

| TC-ID | 연결 AC | 시나리오 | 입력 | 기대 결과 | 유형 | 우선순위 |
|-------|---------|---------|------|---------|------|---------|
| TC-CAP-02-01 | AC-1 | 기존 태그 | "#기존태그" | 태그 매핑 저장 | 통합 | P1 |
| TC-CAP-02-02 | AC-2 | 신규 태그 생성 | "#새태그" | 생성 확인 다이얼로그 | E2E | P1 |
| TC-CAP-02-03 | AC-3 | 자동완성 | "#프로" (기존 태그 존재) | 드롭다운 3개 이하 표시 | 단위 | P2 |
