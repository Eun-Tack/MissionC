## SC-09: Capture Inbox

### 디자인 의도

| 항목 | 내용 |
|------|------|
| 목표 인상 | Triage · Trustworthy · Frictionless |
| 차별 포인트 | Telegram·Voice·Quick Capture를 한 큐로 모아 사용자가 한 번에 검수·확정 |
| 핵심 UX | "1초 안에 수락/거부/태그 수정" — 키보드 단축키 (a/r/t) 우선 |

### ASCII 목업

```
┌──────────────────────────────────────────────────────────────────────┐
│ MC › Inbox                                Pending: 7  Today: 12      │
├──────────────────────────────────────────────────────────────────────┤
│  📩 [Telegram]  09:14                                                │
│     "아이패드 펜슬 충전기 챙길 것"                                      │
│     자동 분류 → ☐ task   #shopping (?)                                │
│     [a 수락]  [r 거부]  [t 태그수정]  [→ 자세히]                      │
│  ─────────────────────────────────────────                           │
│  🎤 [Voice]  09:32  conf=0.78                                        │
│     "오후에 PR 리뷰 다섯시까지"                                        │
│     자동 분류 → ★ schedule  17:00  #mc-dev (?)                        │
│     [a 수락]  [r 거부]  [t 태그수정]                                   │
│  ─────────────────────────────────────────                           │
│  ⚡ [Quick]  09:45                                                   │
│     "OpenVINO IR 변환 시 batch_size=1 필수"                          │
│     자동 분류 → 📝 memo   #mc-dev #note                              │
│     [a 수락]  [r 거부]                                                │
└──────────────────────────────────────────────────────────────────────┘
```

### 데이터 필드

| 필드 | 출처 |
|------|------|
| capture_inbox.source | telegram|voice|quick|gmail |
| capture_inbox.raw_text | 원본 텍스트 |
| capture_inbox.suggested_type | AI 자동 분류 결과 |
| capture_inbox.suggested_tags | JSON array |
| capture_inbox.status | pending → accepted/rejected |
| capture_inbox.accepted_item_id | 수락 시 생성된 items.id |

### 새 비즈니스 규칙

- **BR-INBOX-01**: 모든 외부 capture (Telegram/voice/Gmail)는 inbox로 먼저 들어간다. Quick Capture는 사용자 설정에 따라 inbox 경유 또는 즉시 items 생성 (기본: 신뢰도 < 0.8이면 inbox, 이상이면 즉시).
- **BR-INBOX-02**: pending 상태로 14일 경과 시 expired 처리 (자동 폐기 안 함, 별도 탭).
- **BR-INBOX-03**: 수락 시 capture_inbox.status='accepted' + accepted_item_id 설정. 원본 raw_text는 보존.

### 상태별 표시

| 상태 | 표시 |
|------|------|
| 빈 상태 | "Inbox 비어있음 — 모두 처리됨 ✓" |
| 7일+ 미처리 | 노란 배지 "오래된 항목" |
| AI 자동분류 실패 | "분류 안됨 — 직접 선택" 드롭다운 |

### 디자인 의도

| 항목 | 내용 |
|------|------|
| 목표 인상 | Calm · Recoverable |
| 차별 포인트 | 실패한 작업이 토스트 한 번에 사라지지 않고 한 곳에 누적 → 사용자 재시도 가능 |

### ASCII 목업

```

│ MC › Alerts                                          미확인: 3       │

│     "PR 리뷰 5분 전 알림"                                             │
│     last_error: 401 Unauthorized                                     │
│     [재시도]  [토큰 재등록]  [건너뛰기]                                │
│  ─────────────────────────────────                                   │
│  ⚠ GitHub Rate Limit                                                  │
│     2026-04-28 09:30 → 다음 갱신 10:30                                │

### 새 비즈니스 규칙

- **BR-RETRY-01**: retry_queue 항목은 지수 백오프 (1m → 5m → 30m → 2h, 최대 5회).
- **BR-RETRY-02**: 5회 실패 시 사용자 개입 요청 — UI 배너 + notification_events 기록.
- **BR-NOTIFY-CTR-01**: 모든 토스트는 동시에 notification_events에 기록되어 사용자가 나중에 재확인 가능.

```

### 새 비즈니스 규칙

- **BR-CONFLICT-02**: reject된 버전은 항상 `.conflict-{timestamp}.bak`으로 같은 폴더에 저장된다.
- **BR-CONFLICT-03**: 병합 결정 후 watchdog 이벤트 처리 큐 재개. 병합 미결정 상태에서 추가 외부 편집 시 두 번째 충돌 다이얼로그가 누적된다.
- **BR-CONFLICT-04**: 수동 병합은 좌·우 텍스트영역 + 중앙 결과 텍스트영역 (간단 3-pane). diff 라이브러리 사용 안 함 (V1.0 단순화).
