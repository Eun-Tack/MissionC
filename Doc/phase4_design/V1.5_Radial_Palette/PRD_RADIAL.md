## 1. 페르소나 시나리오

### 시나리오 A: 회의 중 영감 (캡처)
- **상황**: iet03 가 외부 회의 중. 노트북에 ZOOM 띄우고 메모 화면 열려 있음. 갑자기 KBFA 프로젝트 아이디어 떠오름.
- **현재 (V1.0)**: 메모 페이지 → "+" → 입력 → 프로젝트 연결 드롭다운 클릭 → 검색 → 선택 → 저장. **클릭 5회, 7초 이상**.
- **V1.5 목표**: `Cmd+K` → ↑(캡처) → 입력 → Enter. **키보드만, 2초 이내**.

### 시나리오 B: 다른 일 하다가 회고 (모드 전환)
- **상황**: 코드 작성 중. 저녁 회고 시간 알림 받음.
- **현재**: 화면 전환을 위해 마우스 → 좌측 nav → 저녁 회고 클릭. 컨텍스트 단절.
- **V1.5 목표**: `Cmd+K` → ↓(회고) → 즉시 회고 모드. 코드 작성 컨텍스트는 뒤에 *흐릿하게* 유지.

### 시나리오 C: "어제 뭐 했지?" (회상)
- **상황**: 어제 한 결정이 기억 안 남.
- **현재**: 검색 → 키워드 입력 → 결과 스크롤.
- **V1.5 목표**: `Cmd+K` → ←(어제) → 어제 활동 카드 자동 표시.

## 2. FR 정의

### FR-RADIAL-01: 8 슬라이스 진입 (P0)

**한 줄**: `Cmd+K` (또는 `Ctrl+K` on Windows) 입력 시 화면 중앙에 8 방향 방사형 메뉴를 표시한다. `[iet03]`

**진입 트리거** (3 종류):
- 키보드: `Cmd+K` / `Ctrl+K` / `/` (cmdk-like)
- 마우스: 화면 우하단 floating action button (보조)
- 프로그래매틱: `window.openRadial()` (다른 컴포넌트에서 호출)

**8 슬라이스 (시계 12시 시작, 시계방향)**:

| 시각 | 슬라이스 | 핵심 액션 | 단축키 |
|------|----------|-----------|--------|
| 12 | 캡처 | 텍스트 input 표시 → POST `/api/items` (type=task, location=hot) | `↑` 또는 `c` |
| 1.5 | 검색 | inline FTS5 검색바 → 기존 `/api/cmdk` 호출 | `↗` 또는 `s` |
| 3 | 오늘 보기 | 라우팅 `/` (Today's Flow) | `→` 또는 `t` |
| 4.5 | 컨텍스트 패널 | 현재 항목의 컨텍스트 패널 expand (현재 페이지에 의존) | `↘` 또는 `x` |
| 6 | 회고 | 시간대 따라 `/morning` 또는 `/evening` 자동 선택 | `↓` 또는 `r` |
| 7.5 | 어제 컨텍스트 | 어제 활동 카드 모달 (5 항목) | `↙` 또는 `y` |
| 9 | 프로젝트 | 프로젝트 목록 검색바 → `/hierarchy` 또는 `/project/{id}` | `←` 또는 `p` |
| 10.5 | 음성 캡처 | Whisper STT 모달 (FR-AI-VOICE 재사용) | `↖` 또는 `v` |

**비즈니스 가치**: 사용자가 *어디 있든* 1 단축키로 모든 컨텍스트 진입 → 화면 전환 비용 = 0. `[iet03]`

### FR-RADIAL-02: 키보드 우선 인터랙션 (P0)

**한 줄**: 마우스 없이 8 슬라이스를 모두 도달·실행할 수 있어야 한다. `[iet03]`

**조작 방식**:
- 화살표 키: 8방향 → 해당 슬라이스 강조 (회전식 — 우 끝에서 → 누르면 12시 슬라이스로 wrap)
- 단일 문자 단축키: `c/s/t/x/r/y/p/v` → 해당 슬라이스 즉시 실행
- `Enter`: 강조된 슬라이스 실행
- `Esc`: 닫기 (애니메이션 100ms)
- `Tab`: 다음 슬라이스 (선형 순회 보조)

### FR-RADIAL-03: 컨텍스트 인지형 슬라이스 (P1)

**한 줄**: 슬라이스 라벨/액션은 사용자가 현재 보고 있는 페이지에 따라 동적으로 변경된다. `[추론]`

**규칙**:
- 프로젝트 상세 페이지 (`/project/{id}`) 에서 → "캡처" 슬라이스가 자동으로 해당 프로젝트에 연결됨
- 컨텍스트 패널 (`/partial/context/{id}`) 에서 → "컨텍스트 패널" 슬라이스 비활성 (이미 보고 있음)
- inbox 페이지에서 → "캡처" 슬라이스가 *분류로 점프* 로 변경
- 시간대 (오전/오후) 에 따라 → "회고" 슬라이스가 morning vs evening 자동 결정 (BR-RADIAL-04 참조)

### FR-RADIAL-04: 시각 구현 — 글래스 + Spring 모션 (P1)

**한 줄**: 단순 메뉴가 아닌 *물질감 있는* 진입 — 화면이 잠시 흐려지고 슬라이스가 spring 모션으로 펼쳐진다. `[iet03 — 도전적 디자인 선호]`

**시각 사양** (ADR-002 레이어드 렌더링 준수):
- 배경: `backdrop-filter: blur(20px)` + `oklch(0% 0 0/0.35)` 오버레이
- 슬라이스: 원형 SVG 8조각 — 각 조각 hover/focus 시 `oklch(58% 0.18 280 / 0.15)` 글로우
- 모션: `Web Animations API` — 진입 spring(stiffness: 380, damping: 28), 종료 ease-out 100ms
- 중앙 원: 현재 강조된 슬라이스 라벨을 *대형 텍스트* 로 표시 (24px Pretendard SemiBold)

### FR-RADIAL-05: 모든 페이지에서 작동 (P0)

**한 줄**: V1.0 의 13 라우터 모든 페이지에서 동일하게 작동해야 한다. `[iet03]`

**구현**:
- `templates/base.html` 에 1회 include
- 다른 page-level 단축키와 충돌 회피 (e.g. flow.js 의 `Cmd+K` 가 있다면 이쪽으로 위임)
- `<input>`, `<textarea>` 포커스 중 발동 차단 (단, `Cmd+K` 는 forced)

## 3. 비기능 요구사항

| 항목 | 목표 | 근거 |
|------|------|------|
| 진입 응답 | ≤ 100 ms | 사용자 자각 한계 |
| 액션 완료 | ≤ 800 ms 평균 | V1.0 컨텍스트 패널 ≤500ms 와 동일 기준 |
| 키보드 전용 | 100% 도달 가능 | 접근성 + 사용자 의도 (생산성 1순위) |
| 회귀 영향 | 0 | V1.0 기존 기능 영향 없음 |
| 의존성 | 신규 라이브러리 0 | 기존 스택 유지 |

## 4. 측정 가능한 성공 기준

V1.5 출시 후 1주 내 자가 측정 (`[iet03]`):
- `Cmd+K` 사용 빈도 ≥ 일 20회 (브라우저 콘솔 카운터)
- 캡처 시간 (영감 → 저장 완료) 50% 단축 — 사전 측정 비교
- 마우스 사용 빈도 페이지 진입에서 30% 감소
