## 축 1: UX 차별화

### 경쟁사 공통 UX 약점 [Phase0-경쟁사분석]

- **컨텍스트 단절**: Notion·Obsidian 모두 항목 클릭 시 같은 페이지로 *이동*만. 관련 메모·이슈·태그가 한 패널에서 같이 안 보임. (도구 사이 토글 1,200회/일)
- **검색 한계**: Obsidian/Logseq는 FTS만 — 단어 변형·다른 표현 놓침. Notion AI 검색은 클라우드 종속.
- **vault 강제** (Obsidian): 외부 .md 운영하는 1인 사용자에게 큰 마찰.

### 사용자 주요 불편 [Phase1-사용자]

1. 스케줄·프로젝트·정보가 도구 사이에서 단절 [iet03 킥오프]
2. 단순 일정 관리에서 끝나 흐름이 안 보임 [iet03 킥오프]
3. 본인 .md 메모와 일정·프로젝트가 같이 안 떠 컨텍스트 깨짐 [iet03 킥오프]

### UX 차별화 매트릭스

| 차별화 포인트 | 경쟁사 수준 | 우리 목표 (V1.0) | 임팩트 | 난이도 | 근거 |
|------------|---------|-------------|------|------|------|
| **컨텍스트 자동 결합** | Notion/Obsidian: 항목 클릭 → 페이지 이동 | 클릭 즉시 우측 패널: 태그·메모·이슈·진척 동시 표시 (FR-FLOW-03) | 상 | 중 | [Phase1-사용자] iet03 핵심 가치 |
| **의미 검색 디폴트** | Obsidian/Logseq: FTS만 / Notion AI: 클라우드 | 검색 디폴트=의미, FTS는 fallback (FR-AI-SEARCH) | 상 | 중 | [Phase0-경쟁사분석] |
| **외부 .md 자유** | Obsidian: vault 강제 / Notion: .md 미지원 | 단일 원본 + 메타 다중 매핑, LocalDocsHub 자유 | 중-상 | 낮 | [iet03] 명시 결정 |

### UX 전략 결론

**선택**: **컨텍스트 자동 결합** (FR-FLOW-03 컨텍스트 패널)
**이유**: iet03 킥오프 핵심 가치 "연결성"과 직접 일치. 시장 누구도 한 화면에서 풀지 않음. 1인 시나리오의 "도구 토글 비용"을 0에 가깝게 만드는 가장 직접적 효과.

## 축 1-B: 디자인/브랜드 차별화

### 경쟁사 인상 [Phase0-경쟁사분석]

- Notion: 사이드바 트리 폭주, 페이지 깊이 ↑ → 피로감
- Obsidian: 로컬-퍼스트는 좋지만 "조립" 부담 → 답답함
- Sunsama: 밝고 빠르지만 PKM 영역 비어있음 → 한 도구 안 됨

### 디자인 차별화 매트릭스

| 디자인 포인트 | 경쟁사 인상 | 우리 인상 (V1.x) | 영향 | 난이도 | 근거 |
|------------|---------|--------------|-----|------|------|
| **음성=1등 시민** (V1.1+) | 모두 키보드 전제 | Voice Glass UI, 반투명 유리 + 음파 시각화 | 상 | 중 | [iet03] 도전적 UX 요청 + Whisper NPU 결합 |
| **별자리 표현** (V1.2) | 평면 캘린더 | Time Constellation 토글 — 24h 원형 + 곡선 | 중-상 | 중 | [iet03] 혁신 UI 명시 |
| **Quiet · Ambient** | Notion 폭주 / Akiflow 시끄러움 | 침입형 알림 X, 가장자리 펄스 (V2) | 중 | 낮 | always-on 시나리오 적합 |

### 디자인 전략 결론

**선택**: **단계화 디자인 차별화** — V1.0은 표준 단순, V1.1에서 Voice Glass 시그니처, V1.2에서 Time Constellation 추가. 한꺼번에 도전 X (학습 곡선 분산).
**브랜드 키워드**: Personal · Local · Connected · Quiet

## 축 2: 기능 깊이

### 경쟁사 피상적 영역 [Phase0-경쟁사분석]

- 의미 검색: Obsidian/Logseq 부재. Notion AI는 클라우드. → 1인 로컬에서 비어있음.
- 컨텍스트 결합: 모두 *이동* 또는 *백링크 그래프*만. 한 패널 동시 표시 부재.
- GitHub 이슈 통합: Notion/Obsidian/Logseq 모두 부재 또는 약함.
- 음성 입력: 데스크톱 PKM에서 1등 시민 대접하는 도구 없음.

### iet03 한계 언급 [Phase1-사용자]

- "단순 일정 관리에서 끝나 흐름이 안 보임" — 즉 PKM ↔ 캘린더 연결 깊이 부족
- "본인 .md와 일정·프로젝트가 같이 안 떠" — 메타 매핑 깊이 부족
- "Git 등 연동되서 이슈/진척도 모니터링" — 이상적 시나리오로 명시

### 기능 깊이 분석

| 기능 영역 | Notion | Obsidian | Logseq | Sunsama | 우리 V1.0 목표 | 전략 가치 | 전환 비용 |
|---------|--------|----------|--------|---------|-----------|--------|---------|
| 의미 검색 | △ AI(클라우드) | ✗ | ✗ | ✗ | NPU 임베딩 + sqlite-vec | 상 | 높음 |
| 컨텍스트 결합 | △ 페이지 이동 | △ 백링크 그래프 | △ 블록 참조 | ✗ | 우측 패널 즉시 펼침 | 상 | 높음 |
| .md 외부 호환 | ✗ | △ vault 안만 | ◯ md 직접 | ✗ | 단일 원본 + 메타 매핑 | 중-상 | 중 |
| GitHub 이슈 | ✗ | ✗ | ✗ | ✗ | 정식 프로젝트 직접 표시 | 중 | 중 |
| 음성 캡처 | ✗ | △ 플러그인 | ✗ | ✗ | NPU Whisper 실시간 (V1.0) → Glass UI (V1.1) | 중 | 중 |

### 기능 깊이 전략 결론

**선택**: **로컬-퍼스트 의미 검색 (FR-AI-SEARCH)** + **컨텍스트 결합 (FR-FLOW-03)**
**이유**: 둘이 결합되면 시장 누구도 못 푸는 영역(클릭→연결+검색→연결). 진입 장벽 강함. NPU + sqlite-vec는 빠르게 따라오기 어려운 기술 결합.

## 축 3: 기술 우위

### 경쟁사 미채택 유망 기술 [Phase0-기술트렌드]

- **로컬 NPU 임베딩** — 거의 모든 PKM 도구가 클라우드 LLM 의존. Intel/Snapdragon NPU 활용한 의미 검색은 사실상 미채택.
- **sqlite-vec** — 가벼운 벡터 검색이지만 PKM 도구가 채택한 사례 적음.
- **OpenVINO + ONNX Runtime** — Whisper/Phi-3/BGE 모두 변환 가능, NPU 가속 표준 경로.
- **단일 .md 원본 + 인덱스 분리 패턴** — Obsidian이 vault에 모두 묶음, Logseq은 outliner. "원본은 그대로 두고 인덱스만"은 시장 빈자리.

### 기술 우위 분석

| 기술 영역 | 업계 표준 | 우리 V1.0 목표 | 경쟁 장벽 | 출처 |
|---------|--------|-----------|--------|------|
| 임베딩 | 클라우드 (OpenAI ada-002) 또는 ggml CPU | NPU OpenVINO BGE-small 100ms 응답 | 높음 — NPU 활용 + 프라이버시 | [Phase0-기술트렌드] |
| 검색 | Elastic / FTS5 단독 | sqlite-vec + FTS5 하이브리드 (V2 가중치) | 중 — 단순한 결합이지만 PKM에서 드묾 | [Phase0-기술트렌드] |
| 데이터 모델 | DB only or md only | md(원본) + SQLite(메타) 분리 + 다중 매핑 | 중-상 — Obsidian 마찰 회피, 외부 호환 | [iet03] 결정 |
| 패키징 | Electron (무거움) | Python http.server (V1.0) → Tauri (V1.x) | 중 — 1인 개발 단순화, Tauri 마이그레이션 가능 | [Phase0-기술트렌드] |
| LLM (V1.1+) | 클라우드 API | Phi-3 mini INT4 ONNX NPU (V1.1) | 높음 — 데이터 외부 송신 0 + 오프라인 | [Phase0-기술트렌드] |

### 기술 우위 전략 결론

**선택**: **NPU 가속 임베딩 (V1.0) + 로컬 LLM (V1.1+)**
**이유**: 시장에서 "AI 기능"은 거의 모두 클라우드. 로컬 NPU + 프라이버시 + 오프라인은 수년간 변하지 않을 차별점.
> Phase 4 Designer는 Phase 4 PoC(GAP-C-01·02)에서 Intel NPU 실측 검증 후 ADR 작성.

## 축 4: 포지셔닝

### 포지셔닝 맵

```
[프리미엄/전문가]
        │
        │     ● Notion (클라우드, 팀)
        │       ● Tana / Capacities (PKM 신규)
        │
        │  ● Obsidian + Plugins
        │   (로컬, 조립형)
        │
[가성비/대중]──────────[★ MC]──────────[틈새/특화]
        │     ● Logseq (로컬 outliner)
        │
        │  ● Sunsama / Akiflow
        │   (클라우드 데일리 플래너)
        │
[범용/일반]
```

→ MC는 **"가성비/대중"과 "틈새/특화" 사이**, "1인 윈도우 로컬 + 통합 흐름" 빈자리.

### 포지셔닝 정의

| 항목 | 결정 | 근거 |
|------|------|------|
| 가격 포지션 | **개인 무료 / 오픈소스 후보** | [iet03] 1인 사용 / [추론] 시장 진입 가속 |
| 타겟 세그먼트 | **1인 윈도우 지식노동자** (대표·연구자·개발자·창업가, 본업+사이드 다중 트랙) | [Phase1-사용자] iet03 본인 + [추론] 유사 페르소나 |
| 핵심 가치 메시지 | "스케줄·프로젝트·메모·Git이 한 흐름에서 끊기지 않는 로컬 운영 도구" | [추론] Phase 3에서 PRD Vision 검증 |

### 포지셔닝 리스크

| 리스크 | 발생 조건 | 대응 전략 |
|-------|---------|---------|
| 학습 곡선 (V1.2 별자리) | 사용자가 표준 캘린더 익숙 → 별자리 토글 못 켜고 떠남 | V1.2 토글 디폴트 OFF, 가이드 영상 / 메인은 표준 |
| 1인 개발 속도 부진 | 본업 병행으로 V1.0이 6개월 → 1년 늘어짐 | MVP 26 FR로 좁힘 (GAP-H-02 닫음) + Phase 4 PoC 1주 |
| NPU 실측 미검증 | Phase 4 PoC에서 Phi-3 NPU 30초+ 응답 | iGPU/CPU fallback 경로 / V1.1 SLOT 자체를 더 미룰 수 있게 모델 추상화 |
| LLM 시장 빠른 변화 | 1년 후 Phi-3 mini가 더 좋은 모델로 교체 필요 | 모델 인터페이스 추상화 — 모델 파일 swap 가능 (Phase 4 ADR) |
| 1인용 시장 작음 (오픈소스 시 기여 부족) | 사용자 1명 (iet03) → 외부 기여 0 | 기여 안 받아도 OK (사용자 본인용 우선). 향후 일반화는 V2.x 옵션. |

## 최종 선택 — 핵심 차별화 포인트 3가지

| 순위 | 차별화 포인트 | V1.x 도입 | 임팩트 | 실행가능성 | 근거 |
|-----|------------|--------|------|---------|------|
| **1 (Must)** | **컨텍스트 자동 결합** (FR-FLOW-03 컨텍스트 패널) | V1.0 | 상 | 상 | [iet03 핵심 가치] + [Phase0 빈자리] |
| **2 (Should)** | **로컬-퍼스트 의미 검색** (FR-AI-SEARCH BGE-small NPU + sqlite-vec) | V1.0 | 상 | 중 (PoC 의존) | [Phase0 기술] + [Phase1 사용자] |
| **3 (Could)** | **Voice + UX 단계화 시그니처** (FR-AI-VOICE V1.0 → Voice Glass V1.1 → Constellation V1.2) | V1.0~V1.2 | 중-상 | 중 | [iet03 도전적 UX] + [NPU 결합] |
